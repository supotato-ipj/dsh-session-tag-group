# Spec: 会话标签与按标签分组

> 共识来源：2026-11-07 `/grill-with-docs` 问答（Q1–Q13），共识清单 15 条已获用户确认。
> 术语以根目录 `GLOSSARY.md` 为准；架构前提见 `docs/adr/0001-shadow-workspaces-rewrite.md`。

## Problem Statement

DSH 左侧会话列表只有内置的分组/平铺两种组织方式，会话一多就难以定位。用户横跨多个 workspace（法律、工程、GTD 等）工作，希望给自己的对话贴上标签（如项目名「宁兰路桥」「Obsidian」），并在工作区分组选项里新增「按标签」来浏览——尤其是跨 workspace 聚合：两个 workspace 里同属一个项目的对话，能在同一个标签组里相遇。

## Solution

一个纯插件（包名 `@local/dsh-session-tags`，显示名「会话标签」）：

- 会话行菜单新增「编辑标签」：弹层内勾选已有标签、输入新标签即建即挂，取消勾选即移除；
- 浏览区搜索框旁选项按钮菜单的「分组」组别里新增「按标签」项，与原有分组/平铺并列；
- 切到标签模式后，跨 workspace 按标签聚合显示所有会话：多标签会话在每个标签组都出现，未标签会话收进末尾「未标签」组，组内/组间按最近活跃排序，置顶会话仍聚合在列表最上方，会话行标注所属 workspace；
- 归档会话不显示但保留标签关联，删除会话清理关联；搜索框在分组结果内继续可用；分组模式选择跨重启记住。

## User Stories

1. 作为用户，我想给任意会话打一个标签，以便按项目/主题组织对话。
2. 作为用户，我想给一个会话同时打多个标签，以便一个对话归属多个主题。
3. 作为用户，我想在会话行菜单里直接编辑标签，以便不离开列表就完成打标。
4. 作为用户，我想在弹层里勾选已有标签，以便快速复用而不重复输入。
5. 作为用户，我想在弹层里输入新标签名即建即挂，以便标签随用随建、无需预建标签池。
6. 作为用户，我想取消勾选就移除会话上的标签，以便无需专门的管理页。
7. 作为用户，我想在分组选项里切到「按标签」，以便按标签浏览会话。
8. 作为用户，我想随时切回默认模式并看到内置原有行为，以便插件不干扰习惯用法。
9. 作为用户，我想在标签模式下跨 workspace 看到同一标签下的全部会话，以便获得一个项目的全局视野。
10. 作为用户，我想让打了多个标签的会话在每个标签组里都出现，以便从任何角度都能找到它。
11. 作为用户，我想让未打标签的会话收进末尾「未标签」组，以便发现漏打的对话。
12. 作为用户，我想标签组内按最近活跃排序，以便最新对话排在前。
13. 作为用户，我想标签组之间按组内最近活跃排序，以便活跃的组排在前。
14. 作为用户，我想置顶会话在标签模式下仍聚合在列表最上方，以便置顶直觉不失效。
15. 作为用户，我想标签模式下的会话行显示所属 workspace 名，以便跨 workspace 聚合时分清来源。
16. 作为用户，我想归档的会话不出现在标签分组里，以便列表保持干净。
17. 作为用户，我想归档会话的标签关联被保留，以便取消归档后它原样回到原标签组。
18. 作为用户，我想删除会话时其标签关联被自动清理，以便标签池不留死数据。
19. 作为用户，我想在标签模式下继续使用搜索框，以便在分组结果内过滤。
20. 作为用户，我想标签以色点显示在分组头和会话行上，以便快速扫读。
21. 作为用户，我想悬停会话行时看到标签名，以便不打开弹层也能确认打标情况。
22. 作为用户，我想分组模式的选择跨重启记住，以便不必每次重新切换。
23. 作为用户，我想标签池全局共用（不按 workspace 隔离），以便跨 workspace 复用同一套标签体系。
24. 作为用户，我想插件可随时禁用并回退到内置浏览区，以便出现问题时零风险退出。
25. 作为用户，我想标签数据独立于 UI 存储存活，以便 UI 层损坏时不丢失打标记录。

## Implementation Decisions

- **纯插件，Host + Client 双半结构**；Client 半 shadow 内置浏览区整区重写（ADR-0001），复刻搜索、置顶（Pin）标记与排序、归档入口、会话行（状态点、时间标签、悬停卡）与 workspace 对话框（创建/重命名/删除/切换）。内置分组/平铺行为原样保留。
- **标签模型**：多标签 + 全局标签池，随打随建；标签只打在会话上，workspace 本身不带标签。
- **Host 标签服务**：提供标签列出、会话标签设置/移除、会话删除时关联清理；数据经 storage domain 存全局 JSON（Host 侧，独立于 UI 存活）。
- **分组计算纯函数**：输入 =（会话快照列表〔workspace、置顶、归档、最近活跃时间〕＋ 标签映射 ＋ 当前模式），输出 = 有序分组树（置顶聚合 → 标签组 → 未标签组，含行级 workspace 标注）。shadow UI 只是该函数的渲染器。
- **标签模式行为**：跨 workspace 聚合；归档会话排除；组内/组间按最近活跃排序；未标签组垫底；搜索在分组结果内过滤；行上显示 workspace 名。
- **打标弹层**：已有标签勾选列表 + 新标签输入框（回车即建即挂），取消勾选即移除。
- **模式切换控件**：搜索框旁选项按钮菜单的「分组」组别内新增「按标签」项；模式选择持久化于 Host 侧，与标签数据同域。
- **展示资源**：显示名「会话标签」，界面文案中文（含 locale 资源与原创图标）。

## Testing Decisions

- **只测外部行为，不测实现细节**：给定输入断言输出。
- **Host 标签服务**：注入内存 storage backend，测打标/移除、标签池列出、删除会话清理关联、归档保留关联。
- **分组计算纯函数**：覆盖全部分组细则断言——多标签重复出现、未标签组垫底、组内/组间最近活跃排序、置顶聚合最上、行级 workspace 标注、归档排除、空态。
- **UI 不做自动化测试**：shadow UI 装入 desktop profile 后人工验收，与既有自建插件的验收方式一致。
- Prior art：本仓库无既有测试设施，测试从零建，用轻量 Node 测试运行器即可。

## Out of Scope

- agent 打标工具（对话中让 agent 打标签）——二期。
- 标签管理页：重命名/合并/删除标签、颜色选择器——二期（一期色点为固定映射）。
- workspace 级标签继承（给 workspace 打标签、其下会话自动归组）——二期。
- 自动规则打标（按 workspace/标题正则）。
- 内置默认模式任何行为的改动。
- 插件市场发布（仅本机 profile 安装）。

## Further Notes

- 2026-11-07 调研确认无现成插件：官方插件目录约 300 包、插件市场（无索引）、本机已装 bundle 三处均无同类。
- DSH 版本升级后 shadow 区需人工回归（ADR-0001 Consequences）；插件可随时禁用回退。
- 术语使用以 `GLOSSARY.md` 为准；测试 seam 已与用户确认（2026-11-07，纯逻辑层 Node 单测 + UI 人工验收）。
